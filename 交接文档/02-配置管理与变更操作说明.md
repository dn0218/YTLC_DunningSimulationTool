# 02 - 配置管理与变更操作说明

> 来源：`Dunning-交接文档-lastest.docx`。本文覆盖 Dunning 的配置界面、JOB 配置、系统配置项汇总、Dunning 同步表清单，以及变更操作的注意事项（变更记录规范）。

---

## 1. 配置界面一览（Billing Center Portal）

| 界面 | 用途 | 关键说明 |
|------|------|---------|
| **Debt Rule Optimize** | Dunning 规则主配置界面 | Reactivation、MASS、Enterprise、1BN、Auto Dialer、Notification After Bill 均在此界面配置（Rule 树、SQL 绑定、数据赋值、判断条件、Action） |
| **Debt Element** | Dunning 参数配置 | 配置 Dunning SQL 的入参、出参。三种类型：**Variable**（Dunning 界面用，存储计算结果或被赋值）、**Constant**（常量，用于计算或赋值给 Variable）、**Data Field**（可当 Variable 用，正常用于给 Dunning SQL 当入参/出参） |
| **Debt Sql** | Dunning 的 SQL 配置界面 | 维护 Rule 引用的 SQL（即 01 文档中的各条 SQL） |
| **Manual Debt Management** | 号码直接单停/复机 | **临时使用**（单停复机或双停复机），后续会换成 Promise Pay 界面 |
| **Dunning Instance Management** | 查询号码在 Dunning 实例中的状态 | Running=在实例中（需缴费退出）；Completed=缴费后实例状态 |
| **IMEI Blacklist Management** | 查询 IMEI 是否在黑名单 | **需求有变动：查询条件最好只用 IMEI 查询**。IMEI 查询要去 Order Entry 的 SI 详情 → Goods 标签页查看 |
| **Account Special Management** | 查询是否在 CTOS / CTOS Trade 黑名单 | 可点击 Soap Info ID、Message Template 查看发送的请求与 Notification 详细信息 |

## 2. Rule / Action 配置要点

1. **数据赋值传导**：数据赋值中的 key 可以一直传导到后面的 Rule（前面的 Rule 走过且未执行 action 即可）。
2. **Continue On Error**：Action 的该属性配置 `Yes` 表示 action 报错不影响后续 action；默认 `No`。
3. **SCHED_TIME**：配置了才会生成 `DEBIT_ACTION`（由 DebitActionDealJob 延时执行）；不配置则匹配后直接执行——当前业务统一使用延时方式。
4. **manual action tagged 节点**：生产 MASS 流程中存在历史遗留的统计用节点，**不要改动**（详见 01 文档 §1.4）。
5. 判断条件、数据赋值、Action 的截图配置在原 docx 中，逐 Rule 查看。

## 3. 系统配置项（CONFIG_ITEM_PARAM 等）

### 3.1 JOB 数据源配置项

| 配置项 | 说明 |
|--------|------|
| `BILL_NOTIFY_SEARCH_SQL` | JOB 执行类为 `com.ztesoft.zsmart.bss.billing.jobservice.AutoDebitDeal` 且参数 `BILL_NOTIFY=Y` 时**优先使用**此配置项的数据范围 SQL |
| `DEBIT_DEAL_SEARCH_SQL` | JOB 执行类为 `AutoDebitDeal` 时优先查找此配置项；`BILL_NOTIFY_SEARCH_SQL` 未配置时也回落到它 |

> 以上两个配置项都未配置时，JOB 会查询**所有后付费账户**逐个匹配。
> **Dunning 模拟工具会把 CONFIG_ITEM_ID 46/234 的 `DEBIT_DEAL_SEARCH_SQL` 改为 `SELECT ACCT_ID FROM TMP_DUNNING`，且不自动还原**——生产/预生产使用工具前务必确认该配置状态（详见 05 文档 §7）。

## 7. 配置变更记录规范（交接建议）

原 docx 未包含正式变更台账，**建议接手后立即建立**，最低字段：

| 字段 | 说明 |
|------|------|
| 变更日期 / 变更人 | |
| 环境 | PREPROD / PROD |
| 变更对象 | 界面名 + Rule 名（或配置项 / 表名） |
| 变更内容 | 改前值 → 改后值（SQL 粘贴全文） |
| 原因 / 工单号 | |
| 验证方式 | 用哪个账户验证、预期结果 |
| 是否已同步生产 | CTOS 4 项配置要特别标注 |

变更操作流程建议：

1. 预生产在 **Debt Rule Optimize / Debt Element / Debt Sql** 界面修改；
2. 用 Dunning 模拟工具（见 04/05 文档）验证各等级动作正确；
3. 同步配置表（§5 清单）到生产；
4. **同步后必须重新检查 §3.3 的 CTOS 4 项配置**（会被覆盖）；
5. 登记变更记录。
