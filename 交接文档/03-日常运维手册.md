## 2. 常用运维 SQL

> 以下 SQL 均在计费核心库（cc 用户）执行；`:ACCT_ID` 替换为实际账户 ID。

### 2.1 查账户是否欠费 / 欠多少（Is In Debt 口径）

```sql
SELECT TO_CHAR(TO_NUMBER(SUM(NVL(A.SETT_CHARGE, 0) + NVL(A.DUE, 0) +
                             NVL(A.ADJUST_CHARGE, 0) +
                             NVL(A.WRITEOFF_CHARGE, 0)) / 10000),
               'FM9999999999990D00') V_OVERDUE_AMOUNT,
       SUM(NVL(A.SETT_CHARGE, 0) + NVL(A.DUE, 0) + NVL(A.ADJUST_CHARGE, 0) +
           NVL(A.WRITEOFF_CHARGE, 0)) V_OVERDUE_CHARGE
  FROM BILL A, BILLING_CYCLE B
 WHERE A.ACCT_ID = :ACCT_ID
   AND A.BILLING_CYCLE_ID = B.BILLING_CYCLE_ID
   AND B.STATE = 'C'
   AND TRUNC(B.DEBT_DATE) <
       ADD_MONTHS(TRUNC(SYSDATE),
                  -1 * (SELECT NVL(MAX(C.ATTR_VALUE), 1) - 1
                          FROM ACCT_ATTR_VALUE C
                          JOIN ATTR D ON C.ATTR_ID = D.ATTR_ID
                         WHERE C.ACCT_ID = :ACCT_ID
                           AND D.ATTR_CODE = 'POST_PAYMENT_MONTHS'));
```

### 2.2 查账户欠费等级处于哪一级（实例当前状态）

```sql
-- 激活的 Dunning 实例（A=在实例中，C=已退出）
SELECT INST_ID, ACCT_ID, STATE, DUE_DATE, CREATED_DATE
  FROM DEBIT_ACCT_OVERDUE_INST
 WHERE ACCT_ID = :ACCT_ID
 ORDER BY CREATED_DATE DESC;

-- 实例下已生成的各 Rule 动作（DEBIT_RULE_ID 对应等级，见 01 文档等级表）
SELECT R.DEBIT_RULE_ID, R.DEBIT_ACTION_ID, R.EXEC_TIME
  FROM DEBIT_ACCT_OVERDUE_RELA_ACTION R
 WHERE R.INST_ID = :INST_ID
 ORDER BY R.DEBIT_RULE_ID;
```

> Rule ID → 等级对照（MASS 组 4）：14=L0，15=L1，17=L2，18=L3，19=L4，21=L5，23=L6，25=L7，26=L8，27=L9，28=拆机后通知；
> ENT 组 5：31=L0，32=L1，34=L2，35=L3，37=L4，40=L5。

### 2.3 查号码停机状态 / 停机原因

```sql
-- PROD_STATE: A在用 B拆机 D单停 E双停；BLOCK_REASON 第3位='1'欠费单停，'00200000000000'欠费双停
SELECT S.ACC_NBR, P.PROD_STATE, P.BLOCK_REASON
  FROM SUBS S JOIN PROD P ON S.SUBS_ID = P.PROD_ID
 WHERE S.ACCT_ID = :ACCT_ID;
```

### 2.4 查账户是否会被 Dunning 扫到（MASS 入口条件核对）

见 01 文档 §3.1（MASS 入口 SQL），逐段核对：POSTPAID / CUST_TYPE / 属性 / ACCT_ITEM.STATE='C' / POST_AUTO_PAY_SIGN。

### 2.5 DEBIT_ACTION 积压监控

```sql
-- 待执行动作积压（SCHED_TIME 已过但仍 A）
SELECT COUNT(*) FROM DEBIT_ACTION
 WHERE STATE = 'A' AND SCHED_TIME < SYSDATE;

-- 明细
SELECT D.DEBIT_ACTION_ID, D.STATE, D.SCHED_TIME, I.ACCT_ID
  FROM DEBIT_ACTION D
  JOIN DEBIT_ACCT_OVERDUE_RELA_ACTION R ON D.DEBIT_ACTION_ID = R.DEBIT_ACTION_ID
  JOIN DEBIT_ACCT_OVERDUE_INST I ON R.INST_ID = I.INST_ID
 WHERE D.STATE = 'A' AND D.SCHED_TIME < SYSDATE
 ORDER BY D.SCHED_TIME
 FETCH FIRST 100 ROWS ONLY;
```

### 2.6 长期 Running 实例

```sql
-- 缴费后应变 Completed；长期 Running 需核对 Is In Debt 是否仍命中
SELECT INST_ID, ACCT_ID, STATE, DUE_DATE, CREATED_DATE
  FROM DEBIT_ACCT_OVERDUE_INST
 WHERE STATE = 'A'
   AND CREATED_DATE < SYSDATE - 150   -- 超过拆机周期仍 Running 的
 ORDER BY CREATED_DATE;
```

### 2.7 动作执行报错排查

```sql
-- 动作历史状态
SELECT STATE FROM DEBIT_ACTION_HIS WHERE DEBIT_ACTION_ID = :ACT_ID;

-- 报错信息
SELECT ERROR_MSG, *
  FROM DEBIT_RULE_ACTION_INST_HIS
 WHERE INST_ID = :INST_ID AND ERROR_MSG IS NOT NULL;
```

## 3. 常见故障排查

### 3.1 缴费后没有复机（Reactivation 未生效）

1. 用 §2.1 确认欠费是否已清零：`V_OVERDUE_CHARGE <= 10000` 才会退出流程；
2. 核对 Reactivation 各节点（01 文档 §2）：OWB（单停 D+第3位1）、TWO（双停 E）；
3. 双停复机不判断欠费原因，可能双复失败但不影响后续 action——确认 IMEI/CTOS/1BN 退订是否执行；
4. 到 Dunning Instance Management 看实例是否 Completed。

### 3.2 该停机的没停机

1. §2.4 核对入口条件（最常见：属性不对、有自动扣款签约 `POST_AUTO_PAY_SIGN.STATE='A' 且 ERROR_TIMES=0`、欠费 ≤ 10000 分）；
2. 确认实例 DUE_DATE 推算是否被 `POST_PAYMENT_MONTHS` 属性影响（01 文档 §8 口径）；
3. 看该等级 Rule 的动作是否生成但未执行（§2.5 积压——**DebitActionDealJob 分页遗漏已知问题**，重跑 JOB 可补）。

### 3.3 通知没发出去

1. 查动作历史（§2.7）有无报错；
2. 核对 Notification 模板 Code（01 文档各等级表）；
3. Account Special Management → Message Template 看发送明细（CTOS 类）。

### 3.4 Auto-Dialer 数据不同步

1. `10.25.178.66` 检查进程：`ps -ef | grep auto-dialer`，死了用 `./auto-dialer.sh` 拉起（目录 `/home/auto-dialer/auto-dialer/`）；
2. 检查 `application.yml` 中 Oracle / SQL Server 连接；
3. 核对资格条件：`BLOCK_REASON='00200000000000'` 且 PROD_STATE='E'（01 文档 §6.1）；
4. 确认每日 08:00 `DebitActionJobAutoDialer` 是否执行成功。

### 3.5 IMEI / CTOS 黑名单问题

- IMEI 查询只用 IMEI 条件（IMEI Blacklist Management 界面）；IMEI 值去 Order Entry → SI 详情 → Goods 标签页找；
- CTOS 请求明细：Account Special Management → Soap Info ID；
- 预生产同步后 CTOS_URL/USERNAME/PASSWORD/PROXY_HOST 被覆盖 → 按 02 文档 §3.3 恢复。

## 4. 临时操作（谨慎）

| 操作 | 入口 | 注意 |
|------|------|------|
| 号码单停/复机/双停复机 | Manual Debt Management | **临时界面**，后续将替换为 Promise Pay 界面 |
| 手动触发出账短信 JOB | JOB 调度平台 `DebitActionJobNotificationAfterBill` | 参数 `DEBIT_RULE_GROUP_ID=12\|SP_ID=101\|BILL_NOTIFY=Y` |
| 重跑 DebitActionDealJob | JOB 调度平台 | 用于补分页遗漏的动作 |

> 任何手工 DML（改实例状态、改 DEBIT_ACTION）都要先备份原值并登记变更记录（02 文档 §7）。
